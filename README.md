# FlowSync：滴答清单 → Notion FLO.W 单向同步（Linux 后台服务）

FlowSync 是一个跑在 Linux 服务器上的后台服务：把**滴答清单**里的任务单向同步到 Notion「**FLO.W 进阶版**」模板的「我的任务 DB」，并按滴答的清单结构自动绑定 FLO.W 的领域。适合放在 Google Cloud 免费的 e2-micro 这类小 VPS 上一直运行。

- **滴答是唯一数据来源**：任务的新增、修改、完成都在滴答完成，Notion 这边跟随；FlowSync 对滴答**只读**。
- **清单 → 二级领域，文件夹 → 一级领域**：任务自动写入「二级领域」，二级领域再关联到对应的一级领域。
- **页面同步区**：滴答的描述、检查事项（可勾选）、子任务、重复规则写到任务页面最上方，页面其余正文和「下一步做什么？」留给你和 Claude。
- **标签关联项目**：任务打上与 FLO.W 项目同名的标签就自动关联，「项目进度」随之更新。
- **番茄钟同步**：滴答的番茄钟和正计时记录写入 FLO.W「任务番茄数据库」。
- **可切换 Notion 工作空间**：同一时间同步一个空间，各空间的登录和同步状态互相独立。
- **基于官方工具**：发布包自带 Node 运行时、滴答 CLI（`@suibiji/dida-cli`）和 Notion 官方 CLI（`ntn`），不需要另外安装。
- **接口不可用也能跑**：滴答有几个接口不在官方文档里，FlowSync 会自动检测，不可用时改用官方接口或降级，不会整体停摆；`flowsync doctor` 能看到每个接口的情况。

## 在 Google Cloud 免费 VPS 上安装

以 e2-micro（Debian 12 或 Ubuntu，x86_64）为例：

1. 在 Google Cloud 控制台打开这台虚拟机的 **SSH**（浏览器里的终端即可），**用平时的用户，不要切换成 root**。
2. 一行安装（会下载发布包到 `~/.flowsync/app`，并注册开机自启的系统服务）：

   ```bash
   curl -fsSL https://github.com/hengyoungmiao/-notion-flow-/releases/latest/download/install.sh | bash
   ```

3. 运行设置向导，按提示一步步来：

   ```bash
   flowsync setup
   ```

4. 设置完成后启动后台服务，并确认状态：

   ```bash
   sudo systemctl enable --now flowsync
   flowsync status
   flowsync doctor
   ```

以后要升级，重新运行第 2 步的命令即可（配置和同步记录都保留，后台服务会自动重启）。

### 设置向导做了什么

1. **登录滴答**（二选一）：
   - **浏览器授权（推荐）**：向导给出一个授权链接，在你自己电脑或手机的浏览器里打开、同意；浏览器随后会跳到一个 `localhost` 开头、打不开的页面（这是正常的），把**地址栏里那一整条链接**复制回终端即可。
   - **粘贴 access token**：网页版滴答 → 头像 → 设置 → 账户与安全 → API 口令；或者在自己电脑上 `npx @suibiji/dida-cli auth login` 后，从 `~/.config/dida-cli/config.json` 复制 `access_token`。
   - 保存后会立即用官方接口读取一次清单列表来验证。
2. **登录 Notion**（二选一）：
   - **集成 token（推荐服务器使用）**：打开 <https://www.notion.so/profile/integrations> 新建“内部”集成，复制密钥；然后在 Notion 里打开 FLO.W 模板最上层的页面 → 右上角 `···` → **连接** → 选这个集成（这样它才能读写 FLO.W 里的各个数据库）。
   - **Notion 账号登录**：向导给出链接和验证码，在浏览器里确认即可。
3. **识别 FLO.W 任务库**：自动查找「我的任务 DB」（找不到可以粘贴链接），顺着关系字段找到领域库、项目库、番茄库，并在任务库里**新增一个「滴答ID」文本字段**（只新增，不改动模板原有内容）。
4. **领域映射**：显示滴答文件夹/清单和 FLO.W 领域的对应关系（名称一致自动关联，找不到会新建）。
5. **同步范围**：是否同步收件箱、首次同步是否导入最近几天完成的任务、是否同步番茄记录。
6. **预览并首次同步**：列出会新建、关联、更新的任务，确认后**先备份 Notion 任务库**再开始。

之后后台服务自动同步：有变化时 10 秒一轮，空闲时逐步放宽到 60 秒。

## 常用命令

| 命令 | 作用 |
|---|---|
| `flowsync status` | 当前工作空间、上次同步、是否在等确认、今日统计、滴答接口降级情况 |
| `flowsync log -f` | 持续显示同步记录（`-n 100` 看最近 100 条） |
| `flowsync sync` | 立即同步一轮；`--dry-run` 只预览不写入 |
| `flowsync approve` | 确认“大批量变更”并执行 |
| `flowsync pause` / `flowsync resume` | 暂停 / 继续自动同步（重启后保持） |
| `flowsync doctor` | 检查环境、滴答各接口、Notion 权限；`--export` 导出脱敏诊断样例 |
| `flowsync mapping` | 查看领域映射；`flowsync mapping set <清单或文件夹> <领域名 \| auto \| create \| skip>` 修改 |
| `flowsync settings` | 查看设置；`flowsync settings set <名称> <值>` 修改（例如 `deletePolicy abandon`） |
| `flowsync workspace list \| add <名称> \| use <名称> \| remove <名称>` | 管理、切换 Notion 工作空间 |
| `flowsync login dida` / `flowsync login notion` | 重新登录（登录失效时后台服务会暂停，重新登录后自动继续） |
| `flowsync removed` / `flowsync restore <滴答ID>` | 查看在 Notion 删除、已停止同步的任务，恢复同步 |
| `flowsync demo` | 用内置示例数据演示一遍（不连接真实账号） |
| `sudo systemctl status flowsync` / `journalctl -u flowsync -f` | 系统服务状态和输出 |

数据都在 `~/.flowsync/`：`config.json`（配置，权限 600）、`state/`（同步状态）、`logs/`（同步记录，保留 14 天）、`backups/`（首次同步前的备份）。

## 同步规则

### 字段所有权

| 滴答 | FLO.W「我的任务 DB」 | 说明 |
|---|---|---|
| 标题 | 任务 | |
| 状态 | 状态 | 只管“未完成 / 完成 / 放弃”这一层；未完成时保留 Notion 里的具体状态（收集、搁置、待办、执行），新建或重新打开时设为「待办」 |
| 开始/截止时间 | 排期 | 全天、定时、区间都支持，按任务时区换算 |
| 完成时间 | 完成日期 | 重新打开时清空 |
| 所在清单 | 二级领域 | 收件箱任务不设置；只替换同步写入的那一个值，保留你手动加的其它领域 |
| 标签 | 关联项目 | 标签与项目同名时关联；只增删同步写入的项目，你手动加的关联保留；子任务没有匹配的标签时继承父任务的项目；**重复任务不按标签关联** |
| 描述、检查事项、子任务、重复规则 | 页面顶部同步区 | 见下文 |
| 任务 ID | 滴答ID | 用于关联和防止重复创建 |
| 重复规则 | 任务类型 | **重复任务固定为「日程」**（在 Notion 改掉会在校正时改回）；其它任务只在新建时设置：有具体时间点 →「日程」，否则 →「待办」 |

**上表之外的所有内容**（「下一步做什么？」、关联笔记、关联阅读、前置/后续任务、同步区以外的页面正文、手动添加的关联项目等）FlowSync 都**永远不会改动**。「下一步做什么？」留给你和 Claude 按 GTD 的方式填写下一步行动。

同步拥有的字段以滴答为准：如果在 Notion 里改了它们，FlowSync 会在下一次校正（默认每 10 分钟）时改回滴答的值，并在同步记录（`flowsync log`）里标注“已按滴答校正”。

### 页面顶部同步区

每个任务页面的最上方有一个灰色的「🔄 来自滴答清单 · 请在滴答中修改」区块，里面依次是：

- 🔁 重复规则（重复任务才有），例如「每周一、周三 · 按截止日期重复」「每月最后一个周五」「每个法定工作日」；
- ✅ 最近完成记录（重复任务），例如「最近完成：09-20、09-27（共 2 次）」；
- ↖ 父任务链接（子任务才有）；
- 描述：滴答里的 Markdown 原样誊抄（标题、列表、加粗、链接、代码等都会保留格式；附件图片显示为“[图片]”）；
- 检查事项：每项一个可勾选的方格，已完成的打勾；
- 子任务：每个子任务一行，可以点进去，已完成的打勾。

同步区只在滴答里的内容变化时重写，**同步区之外的正文完全归你和 Claude**。在 Notion 里勾选或修改同步区不会回写滴答，下次滴答内容变化时会被覆盖。没有任何内容的任务不会出现同步区。

### 重复任务

- 一个重复任务在 Notion 里**只有一个页面**：「排期」始终是下一次的日期，状态保持未完成；只有在滴答里真正结束这个重复任务时才会标记完成。
- 每完成一次，**不会新建页面**，而是记到这个页面同步区的“最近完成”里；这个任务的番茄记录也都挂在同一个页面下。
- 重复任务的「任务类型」一律是「日程」，并且**不按标签关联项目**（例行事务不计入项目进度；你手动加的关联会保留）。重复任务的子任务也不继承项目。
- 以上两条可以用 `flowsync settings set recurringAsSchedule false` 关闭。升级后第一次同步会把已有重复任务统一改成「日程」，这类只改任务类型的修改不会触发“大批量变更”暂停。

### 标签关联项目

- FLO.W 的「项目进度」按任务的「关联项目」计算。在滴答给任务打上和项目同名的标签（比如 `#网站改版` 对应项目「网站改版」，忽略大小写、空格和标点），任务就会关联到该项目，项目进度随之更新。
- 匹配不上任何项目的标签会被忽略，不会自动新建项目；`flowsync mapping` 可以看到每个标签匹配到了哪个项目。
- 子任务照常单独同步（计入项目进度），父任务的同步区里会列出全部子任务。

### 番茄钟 / 正计时

滴答里**关联到已同步任务**的每一条专注记录（番茄钟和正计时），都会在 FLO.W「任务番茄数据库」里生成一条记录：

| 滴答专注记录 | 任务番茄数据库 | 说明 |
|---|---|---|
| 类型 + 任务标题 + 备注 | 名称 | 例如「番茄钟 · 写周报 — 改稿」「正计时 · 读书」 |
| 关联任务 | 关联任务 | 任务上的「关联番茄」自动出现这条记录 |
| 开始时间 | 开始时间 | 按任务时区换算 |
| 结束时间 | 结束时间 | |
| 专注时长 | 番茄默认时长 | 写入实际专注的分钟数 |

- 番茄库通过任务库的「关联番茄」字段自动找到，**不需要改动模板**。
- 首次同步默认导入最近 30 天的专注记录（`focusImportDays` 可改）；之后新的专注记录大约 1 分钟内同步过去。
- 滴答里修改专注记录（例如补备注、改时间）会同步更新；删除的记录确认后移入 Notion 回收站。
- 用“关联任务 + 开始时间”去重，不会重复创建；在 Notion 里删掉的番茄记录不会再重建。
- 没有关联任务、或关联任务不在同步范围内的专注记录不会同步。
- 用 FLO.W「新增番茄」按钮在 Notion 里手动创建的番茄记录不会被改动。

### 清单归档与删除

- **归档清单**：滴答里一个清单归档后，FlowSync **不做任何同步动作**：其中任务的 Notion 页面保持原样（状态、日期、同步区、番茄记录都不动，也不会删除），也不再检查它们在滴答里的变化。同步记录里写一条“清单已归档，其中的任务不再同步（Notion 保持原样）”。
- **重新打开**清单后恢复正常同步，页面和关联都还在，不会重复创建。
- **删除清单**：清单从滴答的清单列表里消失时，FlowSync 先单独向滴答确认一次（`project get`）：还能查到就当作归档（什么都不做）；确认查不到才算删除，其中的任务按「删除任务」的设置处理（默认移入回收站，页面连同笔记一起，30 天内可在 Notion 回收站恢复），一次超过 5 个同样会暂停等你确认。确认时出错这一轮就先不动，下一轮再确认。先归档、后删除的清单，每天最多再确认一次。如果滴答偶尔返回空的清单列表，这一轮会跳过，不会把任务当成删除。
- `flowsync mapping` 里，归档的清单标为“已归档”，删除的清单标为“已删除”（显示它原来对应的二级领域，30 天后自动移除），都不会报错。以后新建一个同名清单，会自动接回原来的二级领域。

### 删除与安全

- 滴答里删除任务：确认任务确实不存在后，默认把 Notion 页面**移入回收站**（30 天内可恢复）；也可以用 `flowsync settings set deletePolicy abandon`（标记放弃）或 `ignore`（保留不动）修改。
- 任务被移到“不同步”的清单或收件箱（收件箱不同步时）：只解除关联，Notion 页面保留。FlowSync 会先在所有清单里找这个任务，找不到才当成删除。
- 在 Notion「状态」里新增的选项（比如“等待”）会被识别到所在的分组，不会被改回「待办」；任务库的可选字段被删除时，FlowSync 停止写入该字段，并在 `flowsync status` / `flowsync doctor` 里提示，必需字段（标题、状态、排期、滴答ID）按 ID 找不到时会先按名称重新识别（例如删掉后又新建了同名字段），真的找不到才暂停并说明原因。
- 同一条写入失败（例如 Notion 拒绝了某个链接）只记录一次，同样的内容 30 分钟内不再重试，内容变了会立即重试；页面顶部同步区先写新的再删旧的，写入失败时旧内容还在。
- 在 Notion 里删掉的任务页面，下一次需要写入时就会被识别，不会反复报错。
- 同步记录或配置文件损坏时会自动备份原文件：配置从最近一次保存的备份恢复；同步记录重建后按「滴答ID」重新关联已有页面，不会重复创建。
- Notion 里删除了一个同步的页面：FlowSync 尊重这次删除，不再重建；`flowsync removed` 可以查看，`flowsync restore <滴答ID>` 恢复同步（重新创建）。
- **批量变更熔断**：一轮计划删除超过 5 个，或修改超过已关联任务的 20%，这部分会暂停，等你用 `flowsync approve` 确认（新建和关联不受影响；`flowsync status` 能看到明细）。
- 创建前先按「滴答ID」查重，程序崩溃重启或状态丢失都不会产生重复任务。
- 首次同步前自动备份 Notion 任务库（`~/.flowsync/backups/`）。

### 领域结构

- 滴答新增的清单/文件夹会自动在 Notion 新建对应领域（`flowsync settings set autoCreateDomains false` 可关闭）。
- 滴答里改名 → 自动关联或自动新建的领域同步改名；手动指定的领域保留 Notion 原名。
- 清单换到别的文件夹 → 二级领域的「一级领域」关系跟着更新。
- Notion 里删除了某个领域 → 映射标记为“已失效”，相关任务保持原有领域，不会被挪走；可以用 `flowsync mapping set <清单> <领域名>` 重新指定，或 `flowsync mapping set <清单> create` 新建同名二级领域（只会新建一次）。

## 常见问题

**`flowsync doctor` 显示滴答某个接口“不可用”？** 这几个接口不在滴答官方文档里，FlowSync 会自动改用替代方案（例如用官方的 `project data` 逐个清单读取任务），同步照常进行。把 `flowsync doctor` 的输出发给开发者，可以进一步确认。

**提示滴答 / Notion 登录失效？** 运行 `flowsync login dida` 或 `flowsync login notion` 重新登录，后台服务会自动继续。

**Notion 提示找不到任务库或没有权限？** 使用集成 token 时，需要在 Notion 里把 FLO.W 模板最上层的页面“连接”到这个集成。

**全天的多日任务在 Notion 里少一天或多一天？** 运行 `flowsync settings set allDayEndExclusive false`（或 `true`）切换，并用 `flowsync doctor --export` 导出一份脱敏样例发给开发者。

**可以在两台机器上同时运行吗？** 不要。同一时间只在一台机器上运行 FlowSync。

**FlowSync 会读取哪些数据？** 滴答的清单、文件夹、任务、标签、番茄记录和时区设置（只读）；Notion 的 FLO.W 任务库、领域库、项目库、番茄库。滴答 token 由 dida-cli 保存在 `~/.config/dida-cli/config.json`，Notion 集成 token 保存在 `~/.flowsync/config.json`（权限 600）。日志不会记录任何 token。

## 待用真实数据校准

下面这些行为，要看你账号的真实接口返回才能最终确定。运行 `flowsync doctor --export` 会生成一份脱敏 JSON（不含标题和描述），用于逐项确认：

- 全天多日任务的 `dueDate` 是否为“结束日次日 0 点”；
- 滴答各接口在你账号上是否可用（`flowsync doctor` 会逐个检查，不可用的会自动改用替代方案）；
- `project data inbox` 是否可用；
- 重复任务每次完成时生成的记录有什么特征（是否带 `repeatTaskId`）；
- `project list` 是否返回已归档的清单（`closed: true`）——不返回也没关系，消失的清单会先确认，不会被误删；
- `task filter` 一次最多返回多少条未完成任务（诊断样例里有 `openTaskCount`，如果正好是整百整千，可能有上限）；
- 标签的大小写形式、检查事项 `items` 的字段结构；
- 任务是否带有 `modifiedTime` 字段；
- 专注记录关联任务的字段是 `taskId` 还是 `tasks[0]`（两种都已兼容）。

## 开发

```bash
npm ci
npm run typecheck
npm test                 # 单元测试 + CLI 契约测试
npm run build            # 打包成 dist/flowsync.mjs
node dist/flowsync.mjs demo --home /tmp/flowsync-demo
npm run package          # 生成 release/flowsync-linux-<arch>.tar.gz（自带 Node 运行时）
```

发布：在 GitHub Actions 里手动运行 **Build**，勾选“同时发布 GitHub Release”，会按 `package.json` 的版本号创建 `v` 标签并上传发布包和安装脚本。

### 架构

- `src/core/`：同步核心（规划、执行、熔断、映射、同步区、番茄、归档/删除清单处理），与运行环境无关，测试覆盖。
  - `adapters/dida.ts`：通过 dida-cli 只读访问滴答；`adapters/resilient-dida.ts`：接口不可用时的替代方案和降级。
  - `adapters/notion.ts`：通过 ntn 调用 Notion API（固定 API 版本 2026-03-11）。
- `src/app/`：后端服务（工作空间、登录、识别 FLO.W、首次同步）、常驻服务（轮询、请求文件、单实例锁、状态文件）、`doctor` 检查。
- `src/cli/`：命令行和设置向导。
- `scripts/`：打包（`build.mjs`、`package.mjs`）和安装脚本（`install.sh`）。
