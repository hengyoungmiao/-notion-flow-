# FlowSync：滴答清单 → Notion FLO.W 单向同步

FlowSync 是一个常驻 Windows 托盘的小工具：把**滴答清单**里的任务单向同步到 Notion「**FLO.W 进阶版**」模板的「我的任务 DB」，并按滴答的清单结构自动绑定 FLO.W 的领域。

- **滴答是唯一数据来源**：任务的新增、修改、完成都在滴答完成，Notion 这边跟随。
- **清单 → 二级领域，文件夹 → 一级领域**：任务自动写入「二级领域」，二级领域再关联到对应的一级领域。
- **对滴答只读**：FlowSync 永远不会修改或删除滴答里的任何数据。
- **页面同步区**：滴答的描述、检查事项（可勾选）、子任务清单、重复规则写到任务页面最上方，页面其余正文照常由你和 Claude 使用。
- **标签关联项目**：滴答任务打上与 FLO.W 项目同名的标签，就自动关联到项目，FLO.W 的「项目进度」随之更新。
- **番茄钟同步**：滴答的番茄钟和正计时记录写入 FLO.W「任务番茄数据库」并关联到对应任务，FLO.W 的「番茄时长统计」自动计算。
- **可切换 Notion 工作空间**：同一时间只同步到一个空间，各空间的登录和同步状态互相独立。
- **基于官方工具**：内置 Notion 官方 CLI（`ntn`）和滴答官方 CLI（`@suibiji/dida-cli`），不需要另外安装。

---

## 下载安装

1. 打开仓库的 **Actions** 页面，选择最新一次成功的 **Build** 运行，在底部 *Artifacts* 下载 `FlowSync-Windows`（打 `v*` 标签时也会自动发布到 **Releases**）。
2. 解压后运行 `FlowSync-Setup-x.y.z.exe`，按用户安装，不需要管理员权限。
3. 安装包没有代码签名，首次运行 Windows 可能提示“Windows 已保护你的电脑”：点 **更多信息 → 仍要运行**。

## 首次设置

打开 FlowSync 后，设置向导分 6 步：

1. **环境检查**：确认内置的 ntn 和 dida-cli 可用。
2. **登录滴答**：浏览器授权，或粘贴 API 口令（网页版滴答 → 头像 → 设置 → 账户与安全 → API 口令）。
3. **连接 Notion**：点击“登录 Notion”，浏览器会打开授权页，核对界面上显示的验证码后确认；FlowSync 自动找到 FLO.W「我的任务 DB」（找不到时可以粘贴数据库链接），再顺着关系字段找到二级领域库和一级领域库。最后在任务库中**新增一个「滴答ID」文本字段**（只新增，不改动模板原有内容，可以在视图中隐藏）。
4. **领域映射**：滴答文件夹 ↔ 一级领域、清单 ↔ 二级领域。名称一致会自动关联，找不到会新建；也可以手动指定对应关系，或设为“不同步这个清单”。
5. **同步范围**：是否同步收件箱、首次同步是否导入最近几天已完成的任务。
6. **预览并开始**：先看会新建多少任务、关联多少已有任务、新建哪些领域；确认后 FlowSync 会**先备份 Notion 任务库**，再执行首次同步。

完成后 FlowSync 缩在托盘里自动同步：有变化时 10 秒一轮，空闲时逐步放宽到 60 秒；电脑从睡眠唤醒时立即同步一次。

## 同步规则

### 字段所有权

| 滴答 | FLO.W「我的任务 DB」 | 说明 |
|---|---|---|
| 标题 | 任务 | |
| 状态 | 状态 | 只管“未完成 / 完成 / 放弃”这一层；未完成时保留 Notion 里的具体状态（收集、搁置、待办、执行），新建或重新打开时设为「待办」 |
| 开始/截止时间 | 排期 | 全天、定时、区间都支持，按任务时区换算 |
| 完成时间 | 完成日期 | 重新打开时清空 |
| 所在清单 | 二级领域 | 收件箱任务不设置；只替换同步写入的那一个值，保留你手动加的其它领域 |
| 标签 | 关联项目 | 标签与项目同名时关联；只增删同步写入的项目，你手动加的关联保留；子任务没有匹配的标签时继承父任务的项目；**重复任务不按标签关联** |
| 描述、检查事项、子任务、重复规则 | 页面顶部同步区 | 见下文 |
| 任务 ID | 滴答ID | 用于关联和防止重复创建 |
| 重复规则 | 任务类型 | **重复任务固定为「日程」**（在 Notion 改掉会在校正时改回）；其它任务只在新建时设置：有具体时间点 →「日程」，否则 →「待办」 |

**上表之外的所有内容**（「下一步做什么？」、关联笔记、关联阅读、前置/后续任务、同步区以外的页面正文、手动添加的关联项目等）FlowSync 都**永远不会改动**。「下一步做什么？」留给你和 Claude 按 GTD 的方式填写下一步行动。

同步拥有的字段以滴答为准：如果在 Notion 里改了它们，FlowSync 会在下一次校正（默认每 10 分钟）时改回滴答的值，并在「同步记录」里标注“已按滴答校正”。

### 页面顶部同步区

每个任务页面的最上方有一个灰色的「🔄 来自滴答清单 · 请在滴答中修改」区块，里面依次是：

- 🔁 重复规则（重复任务才有），例如「每周一、周三 · 按截止日期重复」「每月最后一个周五」「每个法定工作日」；
- ✅ 最近完成记录（重复任务），例如「最近完成：09-20、09-27（共 2 次）」；
- ↖ 父任务链接（子任务才有）；
- 描述：滴答里的 Markdown 原样誊抄（标题、列表、加粗、链接、代码等都会保留格式；附件图片显示为“[图片]”）；
- 检查事项：每项一个可勾选的方格，已完成的打勾；
- 子任务：每个子任务一行，可以点进去，已完成的打勾。

同步区只在滴答里的内容变化时重写，**同步区之外的正文完全归你和 Claude**。在 Notion 里勾选或修改同步区不会回写滴答，下次滴答内容变化时会被覆盖。没有任何内容的任务不会出现同步区。

### 重复任务

- 一个重复任务在 Notion 里**只有一个页面**：「排期」始终是下一次的日期，状态保持未完成；只有在滴答里真正结束这个重复任务时才会标记完成。
- 每完成一次，**不会新建页面**，而是记到这个页面同步区的“最近完成”里；这个任务的番茄记录也都挂在同一个页面下。
- 重复任务的「任务类型」一律是「日程」，并且**不按标签关联项目**（例行事务不计入项目进度；你手动加的关联会保留）。重复任务的子任务也不继承项目。
- 以上两条可以在「设置 → 重复任务按日程处理」关闭。升级后第一次同步会把已有重复任务统一改成「日程」，这类只改任务类型的修改不会触发“大批量变更”暂停。

### 标签关联项目

- FLO.W 的「项目进度」按任务的「关联项目」计算。在滴答给任务打上和项目同名的标签（比如 `#网站改版` 对应项目「网站改版」，忽略大小写、空格和标点），任务就会关联到该项目，项目进度随之更新。
- 匹配不上任何项目的标签会被忽略，不会自动新建项目；「领域映射」页可以看到每个标签匹配到了哪个项目。
- 子任务照常单独同步（计入项目进度），父任务的同步区里会列出全部子任务。

### 番茄钟 / 正计时

滴答里**关联到已同步任务**的每一条专注记录（番茄钟和正计时），都会在 FLO.W「任务番茄数据库」里生成一条记录：

| 滴答专注记录 | 任务番茄数据库 | 说明 |
|---|---|---|
| 类型 + 任务标题 + 备注 | 名称 | 例如「番茄钟 · 写周报 — 改稿」「正计时 · 读书」 |
| 关联任务 | 关联任务 | 任务上的「关联番茄」自动出现这条记录 |
| 开始时间 | 开始时间 | 按任务时区换算 |
| 结束时间 | 结束时间 | |
| 专注时长 | 番茄默认时长 | 写入实际专注的分钟数 |

- 番茄库通过任务库的「关联番茄」字段自动找到，**不需要改动模板**。
- 首次同步默认导入最近 30 天的专注记录（设置里可改）；之后新的专注记录大约 1 分钟内同步过去。
- 滴答里修改专注记录（例如补备注、改时间）会同步更新；删除的记录确认后移入 Notion 回收站。
- 用“关联任务 + 开始时间”去重，不会重复创建；在 Notion 里删掉的番茄记录不会再重建。
- 没有关联任务、或关联任务不在同步范围内的专注记录不会同步。
- 用 FLO.W「新增番茄」按钮在 Notion 里手动创建的番茄记录不会被改动。

### 清单归档与删除

- **归档清单**：滴答里一个清单被归档后，它下面在 Notion 仍是未完成的任务改为「完成」，「完成日期」填**检测到归档的那一天**（按滴答的时区），同步记录里写明“清单已归档，任务标记完成”。已经完成的任务保留原来的完成日期，二级领域不变；归档清单里从没同步过的任务不会新建页面。
- 检测日期会保存下来：即使因为数量多触发了“大批量变更”暂停、隔天才确认，完成日期仍是检测到归档的那天。
- **重新打开**清单后，恢复按滴答的实际状态同步：未完成的任务改回未完成并清空完成日期，本来就完成的保持完成。
- 可以在「设置 → 滴答清单归档后，其中未完成的任务标记完成」关闭；关闭时只解除关联，页面保持原样，**不会**移入回收站。
- **删除清单**：整个清单在滴答被删除时，它的任务按「删除任务」的设置处理（默认移入回收站），一次超过 5 个同样会暂停等你确认。FlowSync 不会再去滴答查询已删除的清单（避免接口报错导致同步中断）。如果滴答偶尔返回空的清单列表，这一轮会跳过，不会把任务当成删除。
- 「领域映射」页里，归档的清单标为“已归档”，删除的清单标为“已删除”（显示它原来对应的二级领域，30 天后自动移除），都不会报错。以后新建一个同名清单，会自动接回原来的二级领域。

### 删除与安全

- 滴答里删除任务：确认任务确实不存在后，默认把 Notion 页面**移入回收站**（30 天内可恢复）；也可以在设置中改为“标记放弃”或“保留不动”。
- 任务被移到“不同步”的清单或收件箱（收件箱不同步时）：只解除关联，Notion 页面保留。FlowSync 会先在所有清单里找这个任务，找不到才当成删除。
- 在 Notion「状态」里新增的选项（比如“等待”）会被识别到所在的分组，不会被改回「待办」；任务库的可选字段被删除时，FlowSync 停止写入该字段并在概览页提示，必需字段（标题、状态、排期、滴答ID）被删除时会暂停并说明原因。
- 同一条写入失败（例如 Notion 拒绝了某个链接）只记录一次，同样的内容 30 分钟内不再重试，内容变了会立即重试；页面顶部同步区先写新的再删旧的，写入失败时旧内容还在。
- 在 Notion 里删掉的任务页面，下一次需要写入时就会被识别，不会反复报错。
- 同步记录或配置文件损坏时会自动备份原文件：配置从最近一次保存的备份恢复；同步记录重建后按「滴答ID」重新关联已有页面，不会重复创建。
- Notion 里删除了一个同步的页面：FlowSync 尊重这次删除，不再重建；在「同步记录」里可以点“重新创建”。
- **批量变更熔断**：一轮计划删除超过 5 个，或修改超过已关联任务的 20%，同步会暂停并在概览页等你确认（新建和关联不受影响）。
- 创建前先按「滴答ID」查重，程序崩溃重启或状态丢失都不会产生重复任务。
- 首次同步前自动备份 Notion 任务库（「设置 → 备份目录」）。

### 领域结构

- 滴答新增的清单/文件夹会自动在 Notion 新建对应领域（可在设置中关闭）。
- 滴答里改名 → 自动关联或自动新建的领域同步改名；手动指定的领域保留 Notion 原名。
- 清单换到别的文件夹 → 二级领域的「一级领域」关系跟着更新。
- Notion 里删除了某个领域 → 映射标记为“已失效”，相关任务保持原有领域，不会被挪走；可以在「领域映射」里重新指定，或选“新建同名二级领域”（只会新建一次）。

## 切换工作空间

- 「工作空间」页面可以添加多个 Notion 工作空间，每个空间单独登录（登录状态保存在各自的目录，互不影响）。
- 顶部下拉框或托盘菜单即可切换；当前这一轮同步完成后生效。
- 每个空间有自己的同步状态：切回之前的空间时，FlowSync 会自动补齐这段时间滴答里的变化和删除。

> - 「滴答ID」是滴答任务的 ID，可以用 dida CLI 反查对应任务（`dida task get <清单ID> <滴答ID> --json`）。

## 常见问题

**托盘图标变红 / 提示需要重新登录？** 滴答或 Notion 的登录失效了，同步会自动暂停。打开主界面按提示重新登录即可继续。

**找不到 FLO.W 任务库？** 可能当前 Notion 账号没有访问权限，或者库被改了名。可以在向导里直接粘贴「FLO.W - 我的任务 DB」的链接。

**全天的多日任务在 Notion 里少一天或多一天？** 滴答接口对全天区间结束日的存法还需要用真实数据校准。先在「设置 → 日期与时区」切换“截止日为结束日次日 0 点”，并在「设置 → 导出诊断样例」导出一份脱敏样例发给开发者。

**可以在两台电脑上同时运行吗？** 不建议。同一时间只在一台电脑上运行 FlowSync。

**FlowSync 会读取哪些数据？** 滴答的清单、文件夹、任务和时区设置（只读）；Notion 的 FLO.W 任务库、二级领域库、一级领域库。凭据由官方 CLI 保存在本机（滴答：`~/.config/dida-cli/config.json`；Notion：系统凭据管理器）。日志不会记录任何 token。

## 待用真实数据校准

下面这些行为，要看你账号的真实接口返回才能最终确定。应用里的“导出诊断样例”会生成一份脱敏 JSON（不含标题和描述），用于逐项确认：

- 全天多日任务的 `dueDate` 是否为“结束日次日 0 点”；
- `task filter` 不带清单参数时是否包含收件箱，以及 `project data inbox` 是否可用；
- 重复任务每次完成时生成的记录有什么特征（是否带 `repeatTaskId`）；
- `project list` 是否返回已归档的清单（`closed: true`）——“清单归档后标记完成”依赖这一点；
- 标签的大小写形式、检查事项 `items` 的字段结构；
- 任务是否带有 `modifiedTime` 字段；
- 专注记录关联任务的字段是 `taskId` 还是 `tasks[0]`（两种都已兼容）。

## 开发

```bash
npm install
npm run dev:demo      # 演示模式：内置示例数据，不连接真实账号
npm run dev           # 真实模式
npm run typecheck
npm test              # 单元测试 + CLI 契约测试
npm run build && xvfb-run -a npx playwright test test/e2e/app.spec.ts   # 界面测试（演示模式）
npm run build:win     # 打包 Windows 安装包（建议在 Windows 或 CI 上执行）
```

演示模式预设：`FLOWSYNC_DEMO_PRESET=ready` 直接进入已配置状态；`FLOWSYNC_DEMO_PRESET=blocked` 展示批量变更熔断。

### 架构

```
src/core/        纯 TypeScript 同步引擎（不依赖 Electron，全部可单测）
  adapters/      DidaCliReader（只读调用 dida-cli）、NtnNotionClient（ntn api，固定 API 版本 2026-03-11）、内存假实现
  mapping/       日期换算、任务字段映射、领域结构规划
  notion/        FLO.W 结构识别（按属性 ID / 选项 ID 绑定，改名不影响）
  sync/          期望状态对齐引擎：planner（纯函数）+ engine（读取/写入）+ guard（熔断）+ state（每空间 JSON）
  scheduler.ts   自适应轮询、认证失效暂停、错误退避
src/main/        Electron 主进程：内置 CLI 定位、两种登录流程、IPC、托盘、通知、开机自启
src/preload/     contextBridge 白名单 IPC（渲染进程拿不到任何凭据）
src/renderer/    React + Ant Design 中文界面
```
